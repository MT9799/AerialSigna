## 2. 指标

- **Top-1 / Top-3**：按相似度排序，候选是否落在预期区县集合。
- **角度误差**：输出角度与真值之差（合成旋转图）。
- **视场误差**：输出 FOV 与真值 10 km 之差。
- **相似度**：`0.34*NCC_fit + 0.24*hit + 0.22*reverse + 0.20*overlap`，再乘可靠性并加粗排 NCC 先验、减 FOV 偏差惩罚；不是概率，只是排序分数。

### 3.3 真实照片

目前只完成了骨架提取的定性检查：

- 上海外滩：骨架被建筑立面、玻璃反光和黄浦江倒影污染，呈“块状云”而非细线；加入暖色加权与紧凑块过滤后略好，但仍不足以稳定匹配。
- 南京：灯光更暗，骨架断裂严重，适合作为“低信噪比”负例。
- 广州龙溪/增滘：3–4 km 无人机近景，透视强，超出 20 km 县域指纹的主场景；用于验证手动四点矫正。

因此**真实照片尚无 Top-1 准确率数字**，不把合成图结果包装成真实场景结果。

## 4. 失败分析

1. **旋转描述子的插值损失**
   - 方向直方图用 5° 分箱；旋转 18° 会跨 3.6 个箱，线性插值后峰值被抹平；
   - 未旋转时北京方向得分 0.985，旋转后降到 0.697，粗排直接丢失；
   - 解决方向：对查询做 12 个 30° 旋转后各算一次描述子，取最大值；或改用对旋转更鲁棒的傅里叶描述子。

2. **正交网格的 180° 自相似**
   - 粗排可能选到 195°（180°+15°）的翻转解；精排 ±15° 无法回到 18°；
   - 曾尝试精排同时搜索 `a0+180`，但会把精排计算量翻倍，且在当前粗排丢失北京的情况下没有收益，已回退。

3. **视场先验**
   - 合成图 FOV=10，粗排固定 scale=0.5，精排只在 ±4% 内微调，已消除“放大到 11.8 km”的作弊路径；
   - 真实照片的 FOV 未知，仍用 0.40–1.4 的宽搜索。

4. **真实夜景骨架质量**
   - 建筑立面、路灯串、车轨、玻璃反光都会产生亮线；
   - 当前用 top-hat + 暖色加权 + Zhang-Suen 细化 + 紧凑块过滤，仍不足以把“灯光网”提纯到路网级别；
   - 解决方向：多尺度线检测、消失点/透视矫正、按亮线长度和方向一致性做图割。

## 6. 结论

- 全国 2,896 县索引、静态无构建页面、浏览器内匹配、叠加与排序已经端到端跑通。
- 清洁的 10 km 北向灯光图可以稳定排到正确城区（Top-3 全中）。
- 旋转后的全国检索仍会被描述子粗排丢失，是下一阶段的首要算法工作。
- 真实手机/舷窗照片的骨架提纯还没有达到可评估的精度，当前 demo 不宣称真实照片准确率。
